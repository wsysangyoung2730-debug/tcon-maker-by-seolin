# 사진 처리 최적화 — 이슈 #21

## 측정 범위

2026-10-12, Xcode 27.0 / iPhone 17 Pro / iOS 26.5 시뮬레이터에서 동일한 번들 예시 사진과 설정으로 측정했다. 모델 준비 후 엔진 호출부터 결과 반환까지의 시간이며 사진 선택기·HEIC 변환·디스크 기록·화면 전환 시간은 포함하지 않는다. 실기기의 절대 소요 시간과 다를 수 있고, 단일 표본이므로 최초 분석의 작은 차이를 개선율로 해석하지 않는다.

| 작업 | 변경 전 | 변경 후 | 확인한 중복 제거 |
| --- | ---: | ---: | --- |
| 새 사진 첫 분석 | 1,526ms | 1,422ms | 얼굴·배경 분석 각 1회 유지 |
| 밝기·확대 보정 | 45ms | 16ms | 원본 디코딩 1회 → 0회 |
| 저장된 사진 복원 | 576ms | 104ms | 얼굴·배경 분석 각 1회 → 0회, 미리보기 2회 → 1회 |

## 적용 내용

- 밝기·구도 변경은 이미 준비한 인물 이미지와 축소 캐시를 재사용한다. 배경·회전이 바뀌면 필요한 작업을 다시 수행한다.
- 얼굴 좌표·편집 상태를 가져오기 단계에서 적용해 재분석 후 다시 복원하는 중복 과정을 없앤다.
- 정제한 배경 마스크를 Application Support의 `Analysis`에 원본·목록과 분리해 저장한다. 사진 분석 해상도와 최종 원본 해상도는 바꾸지 않았다.
- 캐시는 원본 크기·회전·버전을 확인한 뒤 사용한다. 캐시가 없거나 손상됐으면 원본으로 다시 처리하며 원본과 저장된 편집 상태는 유지한다. 기존 사진함은 첫 복원 시 캐시를 만든다.
- 캐시는 기기 백업에서 제외하며 사진 삭제 시 함께 제거한다. 캐시 저장 실패가 사진 원본·편집 상태 저장을 막지 않는다.
- 사진 한 장 추가 시 해당 사진만 전달하고, 개별 보정은 해당 사진의 편집 상태만 조회한다.
- 안내선 등 렌더링에 영향을 주지 않는 전체 설정 변경은 미리보기를 다시 만들지 않는다.

## 검증

`PhotoPerformanceTests`는 시간 제한 대신 실제 디코딩·얼굴·배경 분석 호출 횟수를 검증한다. 캐시 복원 전후의 미리보기와 원본 해상도 JPG 저장 결과가 바이트 단위로 일치하는지 확인한다. 손상된 캐시 및 캐시 없는 기존 사진함도 같은 결과로 복구되는지 확인한다.

모델·보관함·사진 엔진 테스트 9개가 통과했다. 배경 품질에 영향을 줄 수 있는 모델 교체나 분석 해상도 축소는 이번 변경에 포함하지 않았다. 새 사진의 최초 분석에는 여전히 얼굴 인식과 배경 분리 시간이 필요하다.


## Apple Vision 전환 후 실기기 측정 — 이슈 #27

2026-10-13, iPhone 14 Pro / iOS 26.5 / Xcode 27에서 번들 예시 사진으로 확인했다. 모델 준비 후 엔진 호출부터 반환까지이며 사진 선택기·원본 다운로드 시간은 제외한다.

- 첫 가져오기: 834–940ms (얼굴 분석 322–333ms, 인물 분리 186–272ms)
- 밝기·구도 보정: 15–17ms
- 저장된 분석 결과로 복원: 94–106ms

RVM·Selfie 모델을 제거하고 Apple Vision으로 교체한 이후의 값이다. 위 시뮬레이터 기록과 하드웨어·모델이 다르므로 직접적인 개선율로 비교하지 않는다. 단일 예시 사진의 측정이며 실제 사진 크기·배경·기기에 따라 달라진다. 실기기 테스트에서 캐시 복원 전후 결과의 바이트 일치, 손상·누락 캐시 재분석을 확인했다.
