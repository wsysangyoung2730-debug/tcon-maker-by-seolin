# 검증 기록

검증일: 2026-10-12
환경: Xcode 27.0, iPhone 17 Pro 시뮬레이터 / iOS 26.5

## 자동 검증

- 모델·파일 처리 테스트 3개: 규격 범위, 손상 이미지, 파일명 정리, 이름 충돌, 손상된 내보내기 데이터 확인
- 실제 사진 엔진 통합 테스트 1개: 번들 얼굴·배경 모델 초기화, 얼굴 검출, 규격 비율, 개별 밝기·구도·배경, 전체 적용 시 개별 설정 유지/초기화, 회전·초기화, 선택 삭제·전체 삭제 확인
- 내보내기 검증: JPG 디코딩 및 300KB 제한, 투명 PNG의 알파 채널, 중복 이름이 있는 ZIP 파일의 엔트리 확인
- 화면 흐름 테스트 2개: 홈·규격 설정, 작업 목록→개별 밝기 편집→저장→ZIP 파일 내보내기 창 확인

자동 테스트는 앱에 포함된 생성 예시 인물 사진으로 실행합니다. 실제 수련생 사진을 저장소에 포함하지 않습니다. 파일 내보내기 창 진입까지 자동 확인하며 사용자의 iCloud/외부 저장소에 최종 파일을 쓰는 과정은 포함하지 않습니다.

## 빌드

- iOS 시뮬레이터 Debug 빌드 성공
- 일반 iOS 기기 대상 Release 빌드 성공 (코드 서명 제외)
- `Scripts/sync_engine_bridge.py --check`: JavaScript 연결 소스와 앱 번들 일치 확인

## 폴더 정리 후 회귀 검증

App/Core/Features/Shared/Resources로 실제 폴더와 Xcode 그룹을 일치시킨 후 전체 자동 테스트 6개가 통과했습니다. Swift 파일 18개의 프로젝트 참조가 실제 경로에 연결되고 탐색기에 파일명만 표시되는 것을 확인했습니다. Xcode에서도 새 그룹이 표시되는 것을 확인했습니다.

## 폴더 관리·탭 개편 검증

- 모델·파일·폴더·사진 엔진 테스트 7개, 화면 흐름 테스트 3개: 총 10개 통과
- 폴더 생성·이름 변경, 길게 눌러 두 장 선택, 선택 저장 화면, 한 장만 폴더 이동 확인
- 앱 종료·재실행 후 폴더와 사진 소속 유지 확인
- 폴더 삭제 시 두 사진이 미분류에 남고, 선택한 한 장 삭제 후 재실행해도 나머지 사진만 유지됨을 확인
- 원본 안내 문구가 저장 버튼 아래에 위치함을 화면 좌표로 검증
- TCON·증명사진·여권사진 선택 상태 및 진한 남색 배경 확인
- 재가져오기 후 저장된 회전·구도·밝기·배경·미리보기 복원 일치 확인
- 폴더 개편 후 일반 iOS 기기 Release 빌드 성공 (서명 제외)

현재 사진함은 앱 시작 시 보관한 사진을 순서대로 복구하며, 이슈 #21부터 얼굴 좌표·배경 마스크 캐시를 재사용합니다. 대량 사진함의 시작 시간·메모리 사용량은 실기기에서 추가 점검합니다.

## 화면 및 결과 검토

주요 화면 캡처는 `Design/Implemented`에 보관합니다. 저장 이미지의 얼굴·흰 도복 및 투명 배경 결과를 확인했습니다. 원본 사진 바깥으로 크롭이 확장되면 빈 공간이 포함될 수 있으며 앱에서 확인 필요 상태를 표시합니다.

## 아직 확인하지 않은 항목

실제 iPhone 카메라 촬영, 다양한 HEIC/EXIF·iCloud 파일, 사진 권한 허용/거부/제한별 동작, 사진 앱 최종 저장, 실제 공유 완료, 저메모리 환경, 큰 글자·VoiceOver의 전체 흐름은 실기기 점검이 필요합니다. 시뮬레이터 자동 검증이 App Store 제출 검증을 대신하지 않습니다. 자세한 배포 준비는 [출시 준비](RELEASE.md)를 참고하세요.

## 온보딩·튜토리얼 통합 — 이슈 #17·#18

2026-10-12, Xcode 27.0 / iPhone 17 Pro / iOS 26.5에서 확인했습니다.

- 모델·보관함·사진 엔진 7개, 화면 흐름 6개: 전체 자동 테스트 **13개 통과**
- 첫 실행 환영 화면 → 바로 시작 → 재실행 시 홈 진입 확인
- 안내 닫기 → 환영 화면 복귀, 이전 단계 이동, 건너뛰기 확인
- 예시 사진 선택, 여권 규격·확대 조절, 예시 폴더 생성 확인
- 길게 눌러 선택 시작 → 두 장 선택 → 선택 저장 → ZIP 저장 연습 확인
- 완료 후 실제 미분류 사진 0장, 예시 폴더 미생성, 실제 TCON 규격 유지 확인
- 전체 설정에서 다시 열면 연습 상태가 초기화되며, 닫으면 설정 화면으로 복귀
- 일반 iOS 기기 대상 Release 빌드 성공 (코드 서명 제외)
- 기존 저장소에 반영한 소스·프로젝트가 전체 테스트를 통과한 파일과 일치함을 확인
- 바탕화면 `tcon-maker-by-seolin` 경로에서도 시뮬레이터 Debug 빌드 성공
- 예시 화면은 사진 접근 권한을 요청하거나 실제 파일을 저장하지 않음

화면 캡처 `Design/Implemented/10-onboarding.png`부터 `14-tutorial-save.png`까지를 보관했습니다. 환영 화면의 두 진입 버튼, 규격 선택 강조, 폴더 생성, 다중 선택과 저장 안내를 검토했습니다.


## 사진 처리 최적화·브랜드 적용 — 이슈 #21·#22

2026-10-12, Xcode 27.0 / iPhone 17 Pro / iOS 26.5에서 확인했습니다.

- 모델·보관함·사진 엔진 테스트 9개와 화면 흐름 테스트 6개: 서로 다른 자동 테스트 **15개 통과**
- 최종 아이콘·홈 하단 배치 조정 후 홈·설정 및 첫 실행 온보딩 테스트 2개 재검증 통과
- 유효한 캐시로 복구할 때 얼굴·배경 분석 재실행 없이 한 번만 디코딩·미리보기 생성
- 캐시 복구 전후 미리보기와 원본 해상도 JPG 내보내기의 바이트 일치 확인
- 손상되거나 없는 캐시는 기존 분석 경로로 복구하고 동일한 결과 출력
- 개별 보정 시 원본 재디코딩 생략, 안내선 변경 시 미리보기 재생성 생략
- 성능 측정 범위·시뮬레이터 수치는 [사진 처리 성능](PERFORMANCE.md)에 기록
- 기존 T 심벌과 네 모서리를 유지하고 서린 표장을 우측 하단에 겹친 앱 아이콘 적용
- 홈·온보딩의 오른쪽 하단 서린 원본 로고와 버튼 배치 캡처 검토
- 홈의 사진 선택·촬영 버튼을 하단에 고정해 스크롤 위치와 관계없이 접근 가능
- 최종 소스로 iOS 시뮬레이터 Debug 및 일반 iOS 기기 Release 빌드 성공 (코드 서명 제외)

최종 캡처는 `Design/Implemented/01-start.png`, `10-onboarding.png`에 보관했습니다. 실제 기기에서의 처리 시간은 별도 측정이 필요하며, 처음 가져오는 사진에는 얼굴·배경 분석이 수행됩니다.
